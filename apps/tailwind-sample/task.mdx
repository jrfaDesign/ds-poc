# Task overview

Implement the **BYD Sales** page MVP using the existing multi‑platform design system.  
The goal is to **demonstrate the value of the token‑driven, reusable component architecture** across web (and mobile, if applicable).

You must:

- **Only use design‑system tokens** for spacing, colors, typography, radii, shadows, breakpoints, etc.
- **Never use absolute values** (`px`, raw hex colors, arbitrary numbers).
- **Prefer reusable components** (buttons, cards, tags, layout primitives). If a component does not exist, **define it once and reuse it**.
- Ensure the layout is **responsive** and works from small to large viewports.

---

# Design system constraints

## Tokens

Use only the following token categories (names are illustrative—map to the real system):

(these are just example tokens names. Real token names already exist for tailwind and react-native)

- **Spacing:** `space.0`, `space.1`, `space.2`, `space.3`, `space.4`, `space.5`, `space.6`
- **Radii:** `radius.none`, `radius.sm`, `radius.md`, `radius.lg`, `radius.full`
- **Colors:**
  - **Backgrounds:** `color.bg.page`, `color.bg.surface`, `color.bg.surfaceAlt`, `color.bg.nav`, `color.bg.footer`
  - **Text:** `color.text.primary`, `color.text.secondary`, `color.text.muted`, `color.text.inverse`
  - **Borders:** `color.border.subtle`, `color.border.strong`
  - **Status:** `color.status.live`, `color.status.members`, `color.status.exclusive`, `color.status.public`
  - **Accent:** `color.accent.primary`, `color.accent.secondary`
- **Typography:**
  - **Families:** `font.family.sans`, `font.family.brand`
  - **Sizes:** `font.size.xs`, `font.size.sm`, `font.size.md`, `font.size.lg`, `font.size.xl`
  - **Weights:** `font.weight.regular`, `font.weight.medium`, `font.weight.bold`
- **Shadows:** `shadow.none`, `shadow.sm`, `shadow.md`
- **Breakpoints:** `breakpoint.xs`, `breakpoint.sm`, `breakpoint.md`, `breakpoint.lg`, `breakpoint.xl`
- **Z‑index:** `z.nav`, `z.overlay`, `z.footer`

If a needed semantic token does not exist, **define it once** in the design system (e.g. `color.status.live`) and then use that semantic name—never raw values.

# Page structure and layout

## High‑level layout

Use a top‑level **AppShell** layout:

- **AppShell**:
  - **Props:**
    - `header: ReactNode`
    - `footer: ReactNode`
    - `children: ReactNode`
    - `backgroundColorToken?: TokenColor` (default `color.bg.page`)
  - **Behavior:**
    - Applies page background (`color.bg.page`).
    - Constrains content to a max width using layout tokens (e.g. `layout.maxWidth.page`).
    - Provides vertical spacing between header, content, and footer using `space.*`.

Inside `AppShell`, the content area is a **two‑column responsive layout**:

- **Desktop (`>= breakpoint.md`):**
  - Left column: Filters panel (~25–30% width) (this should be sticky on scroll).
  - Right column: Sales listing grid (~70–75% width) ( for demo purposes provide enought mock data to have a good vertical scroll, assuming 3 per row, something like 14).
- **Mobile (`< breakpoint.md`):**
  - Filters collapse into a **FilterBar** at the top (horizontal chips / summary).
  - Sales listing becomes a single column list.

Use a **LayoutGrid** or **Stack** primitive from the design system:

- **LayoutGrid**:
  - **Props:**
    - `columns: { base: number; md?: number; lg?: number }`
    - `gapToken: TokenSpace`
  - For the main content:
    - `columns={{ base: 1, md: 4 }}`
    - Filters span `1` column on `md+`, Sales span `3` columns on `md+`.

# Responsiveness and platform behavior

## Breakpoints

Use design‑system breakpoints:

- **Mobile (`< breakpoint.sm`):**
  - Single column layout.
  - Filters collapsed into a top **FilterBar** summarizing active filters.
  - Sales cards stacked vertically.
  - Footer sections stacked.
- **Tablet (`>= breakpoint.sm` and `< breakpoint.lg`):**
  - Filters panel above sales grid or as a side panel depending on available primitives.
  - Sales grid: 2 columns.
- **Desktop (`>= breakpoint.lg`):**
  - Two‑column layout: filters left, sales grid right.
  - Sales grid: 3 columns.
  - Footer: 4 columns.

All layout changes must be driven by **breakpoint tokens**, not raw media queries.
